# 01. 프롬프트 최적화 구조

> 대상 모델: **Google Gemini / Nano Banana 2** (`gemini-3.1-flash-image` 계열)
> 목적: 이벤트 KV·3D 아이콘 등 비주얼 에셋 생성 시 일관되고 재현 가능한 프롬프트를 작성하기 위한 7-슬롯 구조 정의

---

## 한 줄 요약

프롬프트를 **7개의 슬롯**(Subject · Style · Composition · Lighting · Rendering · Detail · Constraint)으로 분해해서 작성합니다. 각 슬롯은 모델이 독립적으로 해석하는 "의미 단위"이고, 슬롯을 분리해두면 속성 누수(attribute leakage)가 줄고 재현성이 올라갑니다. Nano Banana 2는 키워드 나열이 아니라 **자연어 문장형 지시**를 선호하므로, 슬롯으로 설계하되 최종 출력은 하나의 서술형 문단으로 합치는 방식을 권장합니다.

---

## 1. 왜 슬롯 구조인가 (이론 배경)

### 1.1 구조화 프롬프트는 "속성-객체 결합"을 강화한다

Feng et al., *Training-Free Structured Diffusion Guidance for Compositional Text-to-Image Synthesis* (ICLR 2023, arXiv:2212.05032)는 프롬프트를 언어적 구성 요소로 분해해 디퓨전 모델의 cross-attention key/value에 개별 바인딩하면 **속성-객체 결합 정확도와 구성 충실도(compositional fidelity)가 향상**된다는 점을 보였습니다. 핵심 메커니즘은 attention map이 "토큰-영역 연결"을 무료로 제공한다는 것이고, 각 개념을 깨끗하게 분리해 인코딩할수록 한 객체의 색이 다른 객체로 번지는 현상이 줄어듭니다.

사람이 직접 쓰는 7-슬롯 프롬프트는 이 메커니즘의 **읽기 쉬운 대응물**입니다. 슬롯 하나하나가 모델이 독립적으로 바인딩할 수 있는 깨끗한 의미 단위 역할을 합니다.

### 1.2 LLM이 먼저 "구성을 계획"하면 더 좋아진다

후속 연구(RPG, *Recaptioning · Planning · Generating*, arXiv:2401.11708)는 LLM이 생성 전에 구성을 계획하도록 하면 복잡한 장면의 품질이 올라간다는 점을 보였습니다. **이것이 바로 02번 메타 프롬프트가 하는 일**입니다 — 주제만 받아서 7-슬롯 구조로 "계획"한 뒤 모델에 넘깁니다.

### 1.3 Nano Banana 2의 공식 권장 구조

Google Cloud의 공식 가이드("The ultimate Nano Banana prompting guide", 2026)가 권장하는 텍스트→이미지 기본 공식은 다음과 같습니다.

```
[Subject] + [Action] + [Location/Context] + [Composition] + [Style]
```

여기에 4가지 핵심 규칙이 붙습니다.

1. **구체적으로 써라** — "정장 재킷"이 아니라 "네이비 블루 트위드 재킷"
2. **긍정 표현을 써라** — "차 없는 거리"가 아니라 "텅 빈 거리" (부정 표현 `no/without`은 약하게 작동)
3. **카메라를 통제하라** — 사진·영화 용어로 앵글, 렌즈, 심도 지정
4. **대화형으로 반복하라** — 한 번에 끝내지 말고 편집 지시로 점진 수정

우리의 7-슬롯은 이 공식을 **실무용으로 확장**한 것입니다. (Action/Context는 Subject·Composition 슬롯에 흡수)

### 1.4 다른 모델과 다른 점

| 구분 | Nano Banana 2 | Midjourney | Stable Diffusion |
|---|---|---|---|
| 입력 방식 | 자연어 문장·대화형 | 키워드 + 파라미터 | 키워드 + 가중치 |
| 강점 | 편집 일관성·공간 추론·텍스트 렌더링 | 순수 예술적 스타일 | 세밀한 기술적 통제 |
| 프롬프트 작성 핵심 | **서술형 "크리에이티브 브리프"** | 키워드 조합 | 토큰 가중치 |

> **실무 시사점:** Nano Banana 2에는 콤마로 끊은 키워드 나열(keyword salad)보다 **강한 동사로 시작하는 서술형 문장**이 더 잘 먹힙니다. 슬롯은 설계 도구로 쓰고, 최종 프롬프트는 자연스러운 문단으로 합치세요.

## 2. 7-슬롯 정의

| # | 슬롯 | 정의 | 작성 포인트 |
|---|---|---|---|
| 1 | **Subject** (주제) | 무엇을 그릴 것인가. 단일하고 명확하게. | 핵심 객체 1개. 모호한 복수·추상 회피 |
| 2 | **Style** (스타일) | 전체 미감·재질·장르 | "glossy plastic 3D icon", "soft clay", "frosted glass" |
| 3 | **Composition** (구도) | 카메라 앵글·배치·여백 | "isometric", "45° top-down", "centered, generous padding" |
| 4 | **Lighting** (조명) | 광원·방향·그림자 | "soft studio lighting from upper-left", "soft contact shadow" |
| 5 | **Rendering** (렌더링) | 렌더 엔진·질감·심도 | "Octane/C4D-style PBR render", "ambient occlusion", "f/1.8" |
| 6 | **Detail** (디테일) | 표면 디테일·마감 | "smooth beveled edges", "subtle specular highlights" |
| 7 | **Constraint** (제약) | 반드시 지켜야 할 조건 | "single object", "plain background", "no text", "1:1" |

### 슬롯별 작동 원리 메모

- **Subject**는 attention의 앵커입니다. 흐릿하면 나머지 슬롯이 붙을 곳이 사라집니다.
- **Style + Rendering**이 "재질감"을 결정합니다. 둘을 분리해두면(스타일=장르, 렌더링=물리 질감) 같은 스타일 안에서 질감만 미세 조정하기 쉽습니다.
- **Composition + Lighting**은 아이콘 **세트 일관성**의 핵심 레버입니다. 카메라 앵글과 그림자 방향을 고정하면 주제가 달라져도 한 세트처럼 보입니다.
- **Constraint**는 Nano Banana의 긍정 표현 규칙을 따라야 합니다. `no text`처럼 불가피한 부정은 짧게, 나머지는 "plain white background"처럼 긍정형으로.

## 3. 구조 설명용 예시 — 플라스틱 3D 아이콘

아래는 **02번 메타 프롬프트가 출력하는 형식**과 동일합니다. 여기서는 구조를 설명하기 위해 삽입합니다. 주제(Subject)만 `돼지 저금통`으로 채운 예시입니다. (금융 아이콘 예시)

### 3.1 슬롯 분해형 (작성·검토용)

```text
[Subject]      A cute piggy bank
[Style]        glossy matte plastic 3D icon, toy-like, soft rounded forms
[Composition]  single object centered, slight 3/4 top-down isometric angle,
               generous even padding around the object
[Lighting]     soft studio lighting, gentle key light from upper-left,
               soft ambient fill, a single soft contact shadow beneath
[Rendering]    high-quality Octane / Cinema4D-style PBR render,
               smooth plastic material with subtle subsurface softness,
               ambient occlusion
[Detail]       smooth beveled edges, subtle specular highlights, clean seams,
               a small coin slot on top
[Constraint]   single object only, plain solid white background, no text,
               no extra props, square 1:1 aspect ratio, centered
```

### 3.2 서술형 합본 (모델 입력용 · 권장)

Nano Banana 2는 아래처럼 **하나의 문단으로 합친 형태**를 더 잘 해석합니다. 위 슬롯을 그대로 흐름으로 연결한 것입니다.

```text
A cute piggy bank rendered as a glossy matte plastic 3D icon with soft,
rounded, toy-like forms. Single object centered with a slight 3/4 top-down
isometric angle and generous even padding. Soft studio lighting with a gentle
key light from the upper-left, soft ambient fill, and a single soft contact
shadow beneath the object. High-quality Octane/Cinema4D-style PBR render with a
smooth plastic material, subtle subsurface softness, and ambient occlusion.
Smooth beveled edges, subtle specular highlights, clean seams, and a small coin
slot on top. Single object only on a plain solid white background, no text, no
extra props. Square 1:1 aspect ratio, centered.
```

> **세트로 뽑을 때:** Subject(`A cute piggy bank`)와 Detail의 주제 종속 부분(`a small coin slot on top`)만 교체하고, 나머지 5개 슬롯은 **글자 그대로 고정**합니다. 이렇게 해야 `금고`, `동전 스택`, `신용카드`, `우산` 등이 한 세트로 보입니다.

---

## 4. 작성 체크리스트

- [ ] Subject가 단수·명확한가
- [ ] Style과 Rendering이 분리되어 재질감을 이중으로 통제하는가
- [ ] Composition·Lighting이 세트 고정용으로 잠겨 있는가 (앵글·그림자 방향·여백)
- [ ] Constraint가 긍정 표현 위주인가 (`no text`만 예외적으로 허용)
- [ ] 종횡비(1:1 등)·배경(plain white)이 명시됐는가
- [ ] 최종 입력은 키워드 나열이 아닌 **서술형 문단**인가
- [ ] 주제만 바꾸면 세트가 유지되도록 변수 슬롯이 1~2개로 한정됐는가
