# AI 이미지 생성 워크플로우 — 통합 가이드

> 대상 모델: **Google Gemini / Nano Banana 2** (`gemini-3.1-flash-image`)
> 구성: **각 문서(1~4)를 소개**하고 내용을 한 벌로 모은 통합본입니다. 항목별 상세는 `01`~`05` 개별 파일 참고.

## 구성 — 각 문서 소개

- **[01] 프롬프트 최적화 구조** — 7-슬롯(Subject·Style·Composition·Lighting·Rendering·Detail·Constraint)이 무엇이고 왜 그렇게 쓰는지. → *프롬프트를 직접 쓰거나 구조를 이해하고 싶을 때.*
- **[02] 단일 프롬프트 세팅** — 주제+스타일을 넣으면 7-슬롯 프롬프트 1개를 뽑아주는 메타(시스템) 프롬프트. 스타일 선택형. → *프롬프트 한 장을 빠르게 얻어 Gemini에 직접 붙여넣고 싶을 때.*
- **[03] Evals 평가·개선** — 만든 프롬프트를 7축으로 채점하고 개선하는 평가 프롬프트(최소 3회·최대 10회, 실패 시 원인 보고). → *프롬프트 품질을 객관적으로 점검·개선하고 싶을 때.*
- **[04] 다중 생성 + 자동화** — 주제 여러 개 자동 선정 → 이미지 일괄 생성·다운로드·정리(Cowork + Image Cowork Setting 스킬). → *세트로 여러 개를 한 번에 뽑고 자동화하고 싶을 때.*

> 이론·논문 근거는 `05_리서치_문서.md`. 아래 0~5장은 위 문서들의 내용을 한 벌로 합친 참고용입니다.

## 0. 핵심 이론 요약 (먼저 읽기)

- **구조화 프롬프트**(Feng et al., ICLR 2023): 프롬프트를 의미 단위로 분해해 cross-attention에 개별 바인딩하면 속성-객체 결합·구성 충실도가 올라간다. → **7-슬롯의 근거.**
- **메타 프롬프트**(Suzgun & Kalai 2024): 프롬프트를 만드는 프롬프트는 표준 대비 평균 +17.1%. → **02번의 근거.**
- **반복 자기개선**(Self-Refine 2023 / Reflexion 2023): 생성→비평→수정 루프 + 반성 메모리. → **03번 루프의 근거.**

## 1. 프롬프트 최적화 구조 (7-슬롯)

프롬프트를 7개 슬롯으로 분해합니다. 각 슬롯은 모델이 독립 해석하는 의미 단위이고, 분리해두면 속성 누수가 줄고 재현성이 올라갑니다.

| # | 슬롯 | 정의 | 예시 |
|---|---|---|---|
| 1 | **Subject** | 단일·명확한 핵심 객체 | a cute piggy bank |
| 2 | **Style** | 미감·재질·장르 | glossy matte plastic 3D icon |
| 3 | **Composition** | 앵글·배치·여백 | centered, 3/4 top-down isometric |
| 4 | **Lighting** | 광원·방향·그림자 | soft key from upper-left, soft contact shadow |
| 5 | **Rendering** | 엔진·질감·심도 | Octane/C4D PBR, ambient occlusion |
| 6 | **Detail** | 표면 디테일·마감 | beveled edges, specular highlights |
| 7 | **Constraint** | 필수 조건 | single object, plain white bg, no text, 1:1 |

**Nano Banana 2 핵심 규칙:** ① 구체적으로 ② 긍정 표현으로(`no text`만 예외) ③ 카메라 통제 ④ 대화형 반복. 그리고 **키워드 나열이 아닌 서술형 문단**으로 입력합니다.

**세트 일관성의 핵심:** Composition·Lighting·팔레트를 고정하면 주제가 달라져도 한 세트로 보입니다. 변수는 Subject(+주제 종속 디테일 1줄)뿐.

## 2. 단일 프롬프트 세팅 프롬프트 (메타 프롬프트)

주제 **+ 스타일(재질)** 을 입력하면 위 7-슬롯 형식으로 프롬프트 **1개**를 출력하는 시스템 프롬프트입니다. Claude Project / Gemini Gem 지침에 붙여넣고 사용 (temperature 0.2~0.4). 일반 채팅에서 `스타일 / 주제`로 던지고, 출력된 프롬프트를 Gemini에 직접 붙여넣어 이미지를 뽑습니다. (여러 개 + 자동화는 4번)

```text
# ROLE
You are a prompt architect for Google Nano Banana 2. Take a SUBJECT and a STYLE
(material) and expand them into ONE fully structured 7-slot image prompt for a 3D
icon in that material. Output exactly one prompt.

# INPUTS
- SUBJECT (required): singular, concrete object.
- STYLE (optional): material/finish. Default "plastic" if omitted.

# MATERIAL PRESETS (pick the block matching STYLE; if not listed, infer in the
# same format). Common to all: Composition + Constraint (below).
#   plastic / frosted glass 2-layer / clay / glossy metal / ceramic
#   → 각 프리셋의 Style·Lighting·Rendering·Detail 4줄은 02 파일 시스템 프롬프트 참고
Common:
  [Composition]  single object centered, slight 3/4 top-down isometric angle, generous even padding around the object
  [Constraint]   single object only, plain solid white background, no text, no extra props, square 1:1 aspect ratio, centered

# RULES
1. SUBJECT singular & concrete; reduce plural/abstract to one iconic object.
2. POSITIVE phrasing only; the single allowed negative is "no text".
3. Fill Style/Lighting/Rendering/Detail from the preset for STYLE (verbatim); if not listed, infer those four lines.
4. Infer a subtle 2-4 word accent suited to subject AND material into the Subject line.
5. Write prompts in ENGLISH. 6. Output BOTH formats below, nothing else.

# OUTPUT FORMAT
--- SLOTS ---
[Subject] / [Style] / [Composition] / [Lighting] / [Rendering] / [Detail] / [Constraint]
--- PROMPT ---
<all slots woven into ONE natural-language paragraph, in slot order>
```

**입력 예시:** `프로스티드 글라스 2레이어 / 선물 상자`

```text
--- SLOTS ---
[Subject]      a gift box with a soft-coral inner core
[Style]        frosted glass 3D icon, two-layer construction — a semi-translucent frosted outer shell over a solid colored inner core, soft satin finish, glassmorphism
[Composition]  single object centered, slight 3/4 top-down isometric angle, generous even padding around the object
[Lighting]     soft studio lighting, gentle key from the upper-left, soft ambient fill, a single soft contact shadow beneath, subtle rim light passing through the glass
[Rendering]    high-quality Octane/Cinema4D-style PBR render, frosted glass material with subsurface scattering and a soft internal glow, ambient occlusion
[Detail]       rounded beveled edges, soft specular highlights on the frosted surface, the colored inner core clearly visible through the translucent outer shell, clean seams, a frosted glass ribbon and bow on top
[Constraint]   single object only, plain solid white background, no text, no extra props, square 1:1 aspect ratio, centered

--- PROMPT ---
A gift box with a soft-coral inner core, rendered as a two-layer frosted glass 3D
icon: a semi-translucent frosted outer shell over a solid colored inner core, soft
satin finish, glassmorphism. Single object centered with a slight 3/4 top-down
isometric angle and generous even padding. Soft studio lighting with a gentle key
light from the upper-left, soft ambient fill, a single soft contact shadow beneath,
and a subtle rim light passing through the glass. High-quality Octane/Cinema4D-style
PBR render with a frosted glass material, subsurface scattering, and a soft internal
glow, ambient occlusion. Rounded beveled edges, soft specular highlights on the
frosted surface, the colored inner core clearly visible through the translucent outer
shell, clean seams, and a frosted glass ribbon and bow on top. Single object only on
a plain solid white background, no text, no extra props. Square 1:1 aspect ratio,
centered.
```

> 재질 프리셋 교체(Frosted Glass·Clay·Glossy Metal·Ceramic)는 `02` 파일 4절 참고. Style·Rendering·Detail 3줄만 바꾸고 나머지는 고정.

## 3. Evals — 평가 및 개선

생성한 프롬프트를 객관적으로 채점하고 자동 개선합니다.

### 새로 정의한 7개 평가축 (1~5점, 가중 합산, 만점 35)

| # | 평가축 | 보는 것 | 가중치 |
|---|---|---|---|
| 1 | 주제 정합성 | Subject 단수·명확, 아이콘으로 인식 | 15% |
| 2 | 스타일 고정성 | 잠긴 플라스틱 스타일 블록 보존 | 20% |
| 3 | 슬롯 완전성 | 7슬롯 모두·올바른 자리 | 15% |
| 4 | 제약 준수 | 긍정 표현·1:1·plain bg·no text·단일 | 15% |
| 5 | 세트 재현성 | 앵글·조명·팔레트 고정 → 세트 일관 | 15% |
| 6 | 모델 적합성 | 서술형·무모순·Nano Banana 강점 활용 | 10% |
| 7 | 재질 구체성 | 구체적 재질·마감·색 | 10% |

### 루프 규칙 (핵심)

- **최소 3회 평가** 후에만 합격 가능 (운 좋은 1회 방지)
- **합격선 = 만점−5 = 30점 이상**
- **최대 10회** 개선 반복
- 채점 전 **근거 먼저**, **temperature 0**, 편향(위치·장황함·자기선호·표면유창성) 차단
- **10회에도 30점 미달 → 루프 중단 + 원인 분석·해결책 강제 출력** (어느 축이 끝내 4점 미만이었는지, 반복 실패 패턴, 구조적 이유, 2~3개 구체 해법, 재시도 권고 or 사람에게 에스컬레이션)

> 평가·개선 프롬프트 전문은 `03_Evals_평가_개선.md` 2~3절. **이미지까지 평가하는 결과물 기준 루프**(멀티모달 심사)는 더 강력한 확장 — 아래 "더 나은 파이프라인" 참고.

## 4. 다중 생성 + 자동화 (+ 오케스트레이션 판단)

> **여기가 "확장성"의 자리입니다.** 주제 여러 개를 한 번에 만들고 이미지 생성까지 자동화하는 건 전부 4번 소속이에요(02는 프롬프트 1개 단발). 재질·개수도 여기서 변수로 받습니다. 이 흐름의 패키지 구현이 **Image Cowork Setting 스킬**입니다.
> **실행 환경 주의:** 이 자동화는 **Cowork**에서 동작합니다(Claude in Chrome으로 브라우저 구동 + 로컬 파일 정리). **일반 채팅창에서는 브라우저 구동·이미지 생성이 안 되므로** 스킬을 돌리면 엉뚱하게 동작합니다. 일반 채팅에서는 02로 프롬프트 1개를 뽑아 직접 Gemini에 붙여넣으세요.

### 흐름 (Image Cowork Setting 스킬이 수행)

1. **브리프 입력** (재질·개수·용도·저장폴더) — 재질·개수는 런타임 변수 (예: 메탈 50개)
2. **주제 N개 자동 선정 → 사용자와 채팅으로 확정** (승인 게이트 ①)
3. **각 주제를 7-슬롯 프롬프트로 생성** (재질 프리셋의 잠긴 스타일, Subject만 변경)
4. **샘플 3개 먼저 생성 → 스타일 확인** (승인 게이트 ②)
5. **나머지 일괄 생성 → 다운로드 → 사용자 지정 폴더에 저장·파일명 정리**

### 오케스트레이션, 써야 할까? → **아니요.**

이 작업은 주제→리스트→프롬프트→생성→다운로드→정리로 이어지는 **순차적·공유 컨텍스트·의존성 높은** 흐름입니다. 멀티에이전트 오케스트레이션의 정반대 조건입니다.

- Anthropic: 멀티에이전트는 **토큰 약 15배**, "모든 에이전트가 같은 컨텍스트를 공유해야 하거나 의존성이 많은 도메인은 부적합."
- 오케스트레이터-워커가 90.2% 향상을 낸 건 리서치처럼 **넓게 병렬화되는** 작업이라서. 이 배치는 아님.
- 원칙: "가장 단순한 해법 먼저."

**정답: 단일 선형 파이프라인 + 서브주제 이미지 생성만 1단계 병렬 팬아웃.** (리드+서브에이전트 구조 ❌, "선형 + 병렬 단계 하나" ⭕)

### 왜 Claude in Chrome + Gemini 채팅인가 (비용)

이 방식의 핵심은 **비용**입니다. Gemini API는 이미지 장당 과금이라 배치 규모가 커질수록 비용이 누적되는데, **Gemini 채팅창은 구독(정액) 한도 안에서 추가 과금 없이** 생성됩니다. Claude in Chrome이 그 채팅 UI를 대신 조작해 사람 손을 더는 것이지, 유료 API로 갈아타는 게 아닙니다. → 평상시 배치는 **브라우저 자동화가 기본**, API는 채팅 한도를 넘기거나 결정론적 대량 처리가 필요할 때의 **오버플로 옵션**.

### 보안·안전 (일반 권장)

브라우저 자동화는 프롬프트 인젝션 위험이 있습니다(레드팀 23.6%→11.2%→최신 약 1%, 단 실제 우회 시연 존재). 권장 수칙: 신뢰 도메인(Gemini)만 허용 · "실행 전 확인" 유지 · 민감한 탭(로그인 계정·결제·개인정보)은 닫고 실행 · 민감·중요 시스템엔 에이전트 연결 안 함 · 다운로드 폴더 격리 · 대량 삭제 전 사람 확인.

### 파일명 규칙

```
YYYYMMDD_프로젝트_주제_스타일_v###.png
예) 20260617_iconset_savings-account_plastic3d_v001.png
```
영문·숫자·하이픈/언더스코어만, ISO 날짜, 3자리 제로패딩, 폴더는 프로젝트→서브주제, README.txt로 규칙 문서화.

## 5. 더 나은 파이프라인 제안 (결론)

생성 자체는 **채팅창 기반 브라우저 자동화**가 비용상 정답입니다(한계비용 0). 아래는 그 위에 얹어 품질·운영을 끌어올리는 개선들입니다 — API 전환이 아니라 **현재 흐름을 더 똑똑하게** 만드는 방향이에요.

1. **결과물 기준 evaluator-optimizer 루프.** 프롬프트만 평가하지 말고, 다운로드된 *이미지*를 멀티모달 심사(Claude/Gemini)에 다시 넣어 03의 7축으로 채점·자동 합격. 채팅 기반에서도 그대로 작동(이미지 첨부 → 채점). 결과물로 루프를 닫는 게 핵심.
2. **프롬프트=버전관리 코드 (DSPy식).** 메타 템플릿·주제별 채움을 repo로 관리 → 점수 재현성·회귀 추적.
3. **2모델 티어링 (채팅 안에서).** Nano Banana 2로 초안·반복(빠름) → 합격한 최종본만 Pro로 재생성(최고 충실도·텍스트). 둘 다 채팅 한도 내에서.
4. **워크플로 저장·예약.** Claude in Chrome의 저장형 워크플로/예약 작업으로 반복 배치를 재사용 — 매번 지시 다시 안 써도 됨.
5. **(스케일 시에만) Batch API.** 채팅 한도를 명백히 초과하는 대량(월 수백~수천 장)·결정론 처리가 필요해지면 그때 검토. 장당 과금이 붙지만 Batch는 ~50% 저렴.
