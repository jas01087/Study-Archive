# 04. 생성 자동화 — Claude in Chrome(Cowork) + Gemini

> 목적: 브리프 입력 → 주제 N개 자동 선정 → 프롬프트 채우기 → 이미지 생성 → 다운로드 → 파일명·폴더 정리까지 자동화.
> 범위: 이 문서는 **여러 개를 한 번에 만드는 다중 생성·자동화**(확장성)의 자리입니다. 프롬프트 **1개**만 필요하면 `02_프로젝트_세팅_프롬프트.md`를 쓰세요.
> 핵심 질문: **이 작업에 오케스트레이션을 쓰는 게 좋은가?** → 결론부터: **아니요. 단일 선형 파이프라인이 맞습니다.**

> **실행 환경 주의 — Cowork 전용.** 이 자동화는 **Cowork**에서 동작합니다(Claude in Chrome으로 브라우저를 구동하고 로컬 파일을 정리). 패키지 구현은 **Image Cowork Setting 스킬**입니다. **일반 채팅창에는 브라우저 구동·이미지 생성 기능이 없으므로** 이 스킬/흐름을 그대로 돌리면 엉뚱하게 동작합니다. 일반 채팅에서는 02로 프롬프트 1개를 뽑아 **직접 Gemini 채팅창에 붙여넣는** 방식으로 쓰세요.

---

## 한 줄 요약

이 작업은 주제→리스트→프롬프트→생성→다운로드→정리로 이어지는 **순차적이고 컨텍스트를 공유하는** 흐름입니다. 멀티에이전트 오케스트레이션의 정반대 조건이라 오케스트레이션은 비용만 늘리고 안정성을 떨어뜨립니다. **단일 선형 파이프라인 + (서브주제 생성 이미지만) 1단계 병렬 처리**가 정답입니다. 그리고 생성은 **Claude in Chrome으로 Gemini 채팅창을 구동**하는 방식이 이 워크플로의 핵심입니다 — API 장당 과금 없이 **구독(정액) 한도 안에서 한계비용 0**으로 이미지를 뽑기 위해서죠. API는 양이 아주 많아 채팅 한도를 넘거나 결정론적 대량 처리가 꼭 필요할 때만 검토하는 **오버플로 옵션**입니다.

## 1. 도구 현황 (2026 중반 기준)

- **Claude in Chrome**: 페이지를 관찰하고 Chrome 자동화 API로 클릭·입력·이동·멀티탭을 수행하는 브라우저 확장. 저장형 워크플로 단축키·예약 작업 지원, Claude Code와 `--chrome` 플래그로 연동.
- **Claude Cowork**: Claude Code의 에이전트 능력을 데스크톱 앱으로 가져온 것. **로컬 파일 읽기/쓰기·이름 변경·정렬·중복 제거·정리**, 보고서 생성, 서브에이전트 조율, 그리고 Claude in Chrome 커넥터로 브라우저 구동. → 이 작업에서 **Gemini를 브라우저로 돌리고 다운로드 이미지를 정리하는 주체**.

> **왜 API가 아니라 Claude in Chrome인가 (핵심):** 이 방식을 쓰는 이유는 **비용**입니다. Gemini API는 이미지 장당 과금이 붙어 배치 규모가 커질수록 비용이 누적됩니다. 반면 **Gemini 채팅창은 구독(정액) 한도 안에서 추가 과금 없이** 생성할 수 있고, Claude in Chrome이 그 채팅 UI를 대신 조작해 사람 손을 덜어줍니다. 즉 "사람이 채팅창에서 일일이 하던 일"을 자동화하는 것이지, 유료 API로 갈아타는 게 아닙니다.

## 2. 오케스트레이션 판단 (이 문서의 핵심)

### 결론: 쓰지 마세요. 단일 선형 파이프라인 + 1단계 병렬 팬아웃.

### 왜 오케스트레이션이 부적합한가 — Anthropic 공식 가이드 근거

1. **토큰 비용.** 멀티에이전트 시스템은 "채팅 대비 약 15배 토큰"을 씁니다(Anthropic, "How we built our multi-agent research system", 2025). 작업 가치가 그 비용을 정당화할 만큼 높아야 하는데, 반복적 아이콘 배치 생성은 그렇지 않습니다.
2. **공유 컨텍스트·의존성.** Anthropic은 "모든 에이전트가 같은 컨텍스트를 공유해야 하거나 에이전트 간 의존성이 많은 도메인은 현재 멀티에이전트에 부적합"이라고 명시합니다. 우리 흐름은 각 단계가 **앞 단계 출력에 의존**(주제→리스트→프롬프트→생성→정리)하는 전형적 순차·공유 컨텍스트라 정확히 이 안티패턴입니다.
3. **병렬성 부족.** 오케스트레이터-워커 패턴이 Anthropic에서 90.2% 성능 향상을 낸 건 리서치가 **넓게 펼쳐지는 병렬 작업**이기 때문입니다. 이 배치 파이프라인은 그렇지 않습니다.
4. **단순함 우선 원칙.** "가능한 가장 단순한 해법을 찾고, 필요할 때만 복잡도를 올려라. 워크플로는 잘 정의된 작업에 예측 가능성과 일관성을 준다"(Anthropic, *Building Effective Agents*).

### 단, 병렬이 정당한 단 한 곳 — 서브주제 팬아웃

서브주제 N개가 정해지면, 그 N개의 이미지를 만드는 일은 **서로 독립적인 하위 작업**입니다. 이건 Anthropic이 말하는 "parallelization / sectioning" 워크플로(독립 하위 작업을 병렬 실행)에 해당합니다. 그래서 권장 형태는:

```
[선형 파이프라인]  주제 → 서브주제 리스트 → 프롬프트 채우기 ─┐
                                                          ├─→ (병렬 팬아웃) 이미지 N개 생성
[선형 파이프라인]  ← 다운로드 ← 파일명·폴더 정리 ←──────────┘
```

= **리드에이전트+서브에이전트 오케스트레이션이 아니라, "선형 파이프라인에 병렬 단계 하나"**.

## 3. 자동화 흐름 (3단계)

### 1단계 — 주제 입력 → 관련 주제 리스트 생성

사용자가 대주제(예: `자산관리`)를 입력하면, LLM이 아이콘화할 만한 하위 주제 리스트를 생성합니다.

```text
입력: "자산관리"
출력(예): 돼지 저금통, 동전 스택, 금고, 신용카드, 우산(보장),
          상승 그래프, 지갑, 통장, 계산기, 방패(보안)
```

### 2단계 — 프롬프트 채우기

각 서브주제를 02번 메타 프롬프트의 Subject 슬롯에 넣어 **주제만 빠진 고정 템플릿**을 완성합니다. (Style~Constraint는 잠금)

### 3단계 — 자동화 지시 (Cowork + Chrome)

**A. 브라우저 자동화 경로 (Cowork + Claude in Chrome) — 기본/권장**

채팅 한도 안에서 추가 과금 없이 돌리는 핵심 경로입니다.

```text
For each subtopic in the list:
  1. Open the Gemini image generation page (trusted domain only).
  2. Paste the woven PROMPT for this subtopic.
  3. Generate. Wait for completion (verify the image actually rendered).
  4. Download the result.
  5. Rename to the naming convention, sort into the project/subtopic folder.
  6. On error (no image / failed download): retry up to 2x with backoff, then
     log and skip — do not hang the whole batch.
Finally: write a README.txt in the output folder documenting the naming rule,
the date, and the subject list. Do NOT delete anything without explicit confirm.
```

**B. API 경로 (오버플로 옵션 — 채팅 한도 초과/대량 처리 시에만)**: `gemini-3.1-flash-image` API는 생성·저장이 결정론적이지만 **이미지 장당 과금**이 붙습니다(Batch API ~50% 저렴). 수백~수천 장 규모를 결정론적으로 돌려야 하고 비용을 감수할 수 있을 때의 선택지이며, 평상시 배치에는 A 경로가 비용상 유리합니다.

### 신뢰성 패턴 (공통)

- **단계마다 검증**: "환경에서 ground truth 확인"(이미지가 실제로 떴는지, 파일이 실제로 저장됐는지)
- **재시도 + 백오프**: 생성·다운로드 실패 시 2회까지
- **멱등 쓰기**: 같은 파일 중복 생성 방지
- **삭제 전 사람 체크포인트**: Cowork은 삭제에 명시적 허가가 필요 — 이걸 활용

## 4. 보안·안전 체크리스트 (일반 권장)

> 브라우저 자동화는 프롬프트 인젝션 위험이 있습니다. Anthropic 레드팀 결과: 방어 없이 **공격 성공률 23.6% → 자율 모드 방어 적용 시 11.2%**, 최신 하드닝으로 적응형 공격에 **약 1%까지** 감소. 다만 **관리되는 것이지 제거된 게 아닙니다** — PromptArmor는 화이트리스트된 `anthropic.com` 도메인을 통해 데이터를 빼내는 실제 인젝션을 시연했습니다.

브라우저 자동화를 쓸 때 권장하는 안전 수칙입니다.

- [ ] **신뢰 도메인(Gemini)만** 접근 허용. 다른 사이트로 못 가게 제한
- [ ] **"실행 전 확인(ask before acting)"** 모드 유지
- [ ] 실행 전 **민감한 탭은 닫기** (로그인된 계정·결제·개인정보 등)
- [ ] **민감·중요 시스템에는 에이전트를 붙이지 않기** (Anthropic은 금융 등 고위험 카테고리를 자동 차단)
- [ ] 다운로드 폴더를 **격리된 작업 폴더**로 한정
- [ ] 대량 삭제·이동 전 **사람이 한 번 확인** (Cowork은 삭제에 명시적 허가 필요)

> **참고 — 생성은 채팅창에서:** 이 워크플로의 핵심은 **Gemini 채팅창(구독 한도 내, 한계비용 0)** 에서 생성하는 것입니다. API는 **장당 과금**이 붙으므로, 채팅 한도를 초과하거나 결정론적 대량 처리가 필요해진 시점에만 검토하세요(이때 Batch API ~50% 저렴). 비용 관점에서는 **브라우저 자동화가 기본, API는 오버플로/스케일 옵션**입니다.

## 5. 파일명·폴더 규칙

### 네이밍 스킴

```
YYYYMMDD_프로젝트_주제_스타일_v###.png
예) 20260617_iconset_savings-account_plastic3d_v001.png
```

### 규칙

- **영문·숫자·하이픈/언더스코어만.** 공백·`& ? / *` 등 특수문자 금지 (OS·자동화에서 깨짐)
- **ISO 날짜(YYYYMMDD)** 로 시간순 정렬
- **3자리 제로패딩(v001)** 으로 10개 넘어가도 정렬 유지
- 짧지만 의미 있게, 약어는 팀 합의
- **폴더는 프로젝트 → 서브주제** 순으로
- 폴더에 **README.txt**로 규칙·날짜·주제 리스트 문서화 (DAM 있으면 메타데이터 병행)

### 폴더 구조 예시

```
iconset_자산관리_20260617/
├── README.txt
├── savings-account/
│   ├── 20260617_iconset_savings-account_plastic3d_v001.png
│   └── 20260617_iconset_savings-account_plastic3d_v002.png
├── coin-stack/
│   └── 20260617_iconset_coin-stack_plastic3d_v001.png
└── safe-vault/
    └── 20260617_iconset_safe-vault_plastic3d_v001.png
```
